## 1. Ownership and scheduling

**Bound `hid-steam`, no raw client.** The 2026 USB identity is in the kernel HID table ([K 2751–2755](https://github.com/torvalds/linux/blob/cee9395acd8043be0644b25c34bfa86623f2b935/drivers/hid/hid-steam.c#L2751-L2755)); the wired IBEX interface filter tests HID collection usage, not an actual USB interface number ([K 1602–1630](https://github.com/torvalds/linux/blob/cee9395acd8043be0644b25c34bfa86623f2b935/drivers/hid/hid-steam.c#L1602-L1630)). With `connected && !client_opened`, asynchronous connection work registers kernel evdev gamepad and sensor devices. Neither successful UHID probe nor a physical host result is established ([K 1372–1420,1461–1485](https://github.com/torvalds/linux/blob/cee9395acd8043be0644b25c34bfa86623f2b935/drivers/hid/hid-steam.c#L1461-L1485)).

**Bound `hid-steam`, a consumer opens the virtual HID raw client.** The driver's `client_hdev` open increments `client_opened`; close decrements it. Both schedule connection work. Raw frames are forwarded to `client_hdev`; while open, 54-byte `0x42` and 46-byte `0x45` are not decoded to kernel evdev. Scheduled work unregisters the kernel's synthetic evdev devices while opened, then re-registers on final close if connected. These are **asynchronous transitions**: no instant unregister, precise ordering, or userspace open exclusivity guarantee is implied ([K 1650–1694,1461–1485,2530–2589](https://github.com/torvalds/linux/blob/cee9395acd8043be0644b25c34bfa86623f2b935/drivers/hid/hid-steam.c#L2530-L2589)). Kernel battery `0x43` and connection `0x79` paths do not take the same `client_opened` early-return branch ([K 2590–2617](https://github.com/torvalds/linux/blob/cee9395acd8043be0644b25c34bfa86623f2b935/drivers/hid/hid-steam.c#L2590-L2617)); don't assert they are suppressed.

**Settings contention.** The IBEX evdev open/close callbacks deliberately **do not** toggle lizard settings, unlike the old Controller branch. Sensor FD open/close can issue IMU `SETTING_IMU_MODE` feature SETs, **unless `client_opened`** is nonzero. Registration attempts optional serial and attributes GETs and sets lizard per kernel policy even without an SDL client ([K 909–976,1372–1411](https://github.com/torvalds/linux/blob/cee9395acd8043be0644b25c34bfa86623f2b935/drivers/hid/hid-steam.c#L909-L976)). The Menu bit-6 hold schedules a nominal 450 ms mode switch only through kernel input decoding, with release cancellation and an `lizard_mode` module-policy check. While a raw client suppresses kernel `0x42`/`0x45` decoding, that **normal** Menu-scheduling route is also skipped, without proving what Steam or SDL do with the same press ([K 2441–2458,1487–1515](https://github.com/torvalds/linux/blob/cee9395acd8043be0644b25c34bfa86623f2b935/drivers/hid/hid-steam.c#L2441-L2458)).

**SDL HIDAPI** selects direct Triton by recognized VID/PID without an interface-number condition; its *receiver* branch instead filters interfaces 2–5 ([S 429–451](https://github.com/libsdl-org/SDL/blob/6defbc0129b5ba90bab3f6c67bbc1e9329e24ff1/src/joystick/hidapi/SDL_hidapi_steam_triton.c#L429-L451)). On an active joystick, its update loop tries lizard-disable at a 3 s interval, and sensor opt-in sends its own IMU feature setting. The 3 s interval is host policy, **not** observed physical watchdog expiration ([S 127–144,494–505,653–676](https://github.com/libsdl-org/SDL/blob/6defbc0129b5ba90bab3f6c67bbc1e9329e24ff1/src/joystick/hidapi/SDL_hidapi_steam_triton.c#L653-L676)).

**Steam client:** closed-source device-open and 2026 per-device arbitration path **No evidence**. Valve's public udev rules are permissions evidence, **not** a trace of client device operations. Whether a Steam client and SDL simultaneously open raw handles, which settings win, and each client's mode restoration behavior: **No evidence**.

**Kernel unbound / older kernel:** v7.2 lacks the 2026 IBEX IDs in the inspected `hid-ids.h`. *Inferred:* an ordinary pre-7.3 kernel does not bind the 2026 `hid-steam` path for `28de:1302`; the underlying `hidraw` path can remain available under another driver. This does **not** establish what `hid-generic` evdev reports, whether a specific 6.12 distribution patched the driver, or whether SDL/Steam actually accepts that host. **Inferred, buildout to verify.** [K− 1373–1376](https://github.com/torvalds/linux/blob/8d3ae59288f1e7d58d76558a6ee96d533bc5019f/drivers/hid/hid-ids.h#L1373-L1376).

## 3. Step-16 lab sequence (all **not run**)

1. **Preflight:** record kernel release, `hid-steam` module ID table/binding, VID/PID and HID bus, actual hidraw/evdev enumeration, SDL binary/version/HIDAPI hints, per-node permission results and Steam-client build/channel. Record `lizard_mode` module setting; this cannot be assumed default on downstream builds. Avoid documenting identifying host paths, real serials or MACs in public corpus.
2. **Baseline, bound:** create one source-derived direct-wired candidate; verify binding and 1) evdev-only open, 2) SDL-only hidraw, 3) Steam-only, 4) both open orders SDL→Steam and Steam→SDL. For each, record **counts of clients** only where observable (do not claim `client_opened` is userspace-visible), evdev disappearance/reappearance, input `0x42`/`0x45`/`0x47` decoded controls, mode changes, exact output/feature commands and return codes. Include Menu held shorter and longer than nominal 450 ms with and without a raw client.
3. **Unbound comparison:** use an authorized **per-device**, reversible binding change or a verified older kernel without 2026 matching; do not disable globally. Repeat four rows with actual sysfs binding and discovered devices captured. SDL-only on Anders's 6.12 host is **inferred to work; untested**.
4. **Permissions and failure:** run under ordinary logged-in user with udev rule presence/access checked, then explicitly compare denied hidraw and uinput; do not grant universal access for the sake of the test. Unbind/rebind/close experiments must restore original state even on failure.
5. **Pass gates:** record independently (a) identity discovery (b) successful open (c) live decoded controls (d) lizard output command and observed effect (e) IMU, battery, feedback (f) simultaneous-consumer arbitration and (g) removal/cleanup. A successful open alone is **not** gameplay acceptance.

## 4. Distinct decision implications

- **Compat:** accept both kernel registration commands and SDL's periodic single-setting lizard disable; never require one universal feature order. Send common `0x42` input rather than SDL-only `0x47`; preserve source-specific modes only when deliberately exercised. This is a *proposed software accommodation*, not retail-device truth.
- **Faithful:** real kernel-versus-SDL arbitration, physical lizard watchdog expiration, actual Steam-client mode changes, and default reports remain **No evidence** without owner physical/host capture.
- A source-supported `client_opened` handoff **does not** mean SDL and Steam have proven exclusive access; Linux `hidraw` and the kernel's virtual client are not a protocol-level application ownership guarantee.
- This document provides buildout **inputs** for step 14b/C6 and step 16; it does **not** claim a step on #176.

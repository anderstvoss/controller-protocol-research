# Decision brief — Dolphin Linux MotionPlus attachment

**Recommendation to Anders:** Keep `hid-wiimote` bound. Confirm the **MotionPlus-only** path with owner-imported calibration, then test **two narrowly scoped, source-backed model additions** for MotionPlus+Nunchuk: first a readable **`A400F6/4` downstream-extension identity mirror**, then **`A40040/16` downstream calibration copied from caller-supplied data**. Test each gate before making the next change. **Do not start by unbinding the kernel driver or inventing calibration bytes.**

[Full pinned technical investigation](wii-dolphin-attachment-technical.md) gives each command, reply, mode transition, retry and source line. This is a *source-only* analysis, not a host acceptance test. Dolphin master `3eb30c7620b4` (GPL-2.0-or-later), Linux v6.12 (GPL-2.0-only) and virtualgamepad main `5a11e507ac97` (AGPL-3.0) were inspected. Native ARM64 Dolphin 2503 is reported to connect to the owned Bluetooth-bus UHID `057e:0306`; its exact source/binary equivalence to pinned master is **not independently verified**.

## 1. Attach path and where our device stands

| Stage, in order | Dolphin requires | Current status / meaning |
|---|---|---|
| **1. Connect** | Linux HIDAPI enumerates a Wii name/known ID, opens hidraw, sends status request `0x15`, reconnects to ControllerInterface. No real L2CAP required. | **Reported working** in native Dolphin 2503. Raw HID recognition alone does not establish the gyro decoder. [Scanner](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/Core/HW/WiimoteReal/IOhidapi.cpp#L61-L163). |
| **2. Configure basic input** | Status `0x20`; LED `0x11` ACK; reporting mode **0x37** via `0x12` ACK; EEPROM `0x0016/8` via `0x17` data reply. | **Supported if the EEPROM image is imported.** Empty source images return error 8; Dolphin cannot advance without successful calibration. [Dolphin](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L340-L435). |
| **3. Configure IR and speaker** | `0x1a`/`0x13` IR ACKs, B00000/9 and B0001A/2 sensitivity, B00033/1 mode, B00030/1 tracking; `0x19` speaker mute and `0x14` disable ACKs. | **Supported in current bounded model**; no lightgun/speaker playback claim. A failed write/ACK stops further setup. [Dolphin](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L899-L1047); [model](https://github.com/anderstvoss/virtualgamepad/blob/5a11e507ac973c23ca10beb36edb44fc35034376/crates/gr-curated-controllers/src/wii_remote/memory.rs#L130-L162). |
| **4. Identify and activate MP** | If port reports an extension, A400FB=00 and A400FA/6 first. Poll inactive **A600FE/1**, initialize **A600F0=55**, write mode **A600FE=04/05/07**, wait/recheck active **A400FA/6** after status transitions. | **Supported conditionally**, but kernel and Dolphin may reset the same registers. Dolphin can select mode **05 even with no Nunchuk**. [Dolphin](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L449-L575). |
| **5. Read downstream identity, *only when MP+extension*** | Active MP with downstream-connectivity flag true triggers **A400F6/4**, which Dolphin interprets as mirrored downstream identity (not MP identity at FA). | **Refused: error 7.** This blocks downstream identification and repeated setup **before** reaching MP calibration in this branch. **First proposed model fix.** [Dolphin](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L543-L566); [model](https://github.com/anderstvoss/virtualgamepad/blob/5a11e507ac973c23ca10beb36edb44fc35034376/crates/gr-curated-controllers/src/wii_remote/memory.rs#L253-L285). |
| **6. Read MP gyro calibration** | With stable desired mode, **A40020/32**; then decode active MP samples from **0x37**, using calibration to calculate gyro. | **Supported if caller supplies a valid 32-byte MP block.** The installed application may still need mode/status stability. No default or guessed checksum. [Dolphin](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L574-L605), [gyro gate](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L1450-L1468). |
| **7. Read downstream calibration, *only when identified*** | Under active MP, **A40040/16**; normally inactive accessory uses **A40020/16**. | **Refused: error 7.** **Second model gap**, but crucially this read occurs **after** the MP calibration read, so it need not prevent the first gyro sample. [Dolphin](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L606-L659); [model](https://github.com/anderstvoss/virtualgamepad/blob/5a11e507ac973c23ca10beb36edb44fc35034376/crates/gr-curated-controllers/src/wii_remote/memory.rs#L278-L306). |

**MP-only:** basic setup → poll/activate/confirm MP → A40020/32 → actual changing 0x37 gyro. No F6 or 40 read is required without a downstream extension. The unmerged [W8 PR #45](https://github.com/anderstvoss/controller-protocol-research/pull/45) *provisionally* reports changing Dolphin MP-only gyro in mapping view; it is **not merged into the 138-claim baseline**.

**MP+Nunchuk:** basic setup → identify normal extension when inactive → map MP to 05 → process status/embedded downstream port event → **F6 downstream ID** → stable mode → **20 MP calibration** → **40 Nunchuk calibration** → interleaved 0x37 gyro/Nunchuk. Dolphin may repeat these stages after its **2-second MotionPlus wait** or an extension-port status event; a failed read or ACK can retry or stall. [State machine](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L449-L741).

## 3. Kernel competition trade-offs

Linux v6.12 `hid-wiimote` sends A400F0/FB extension reset, A600F0/FB MP init, A400FA/A600FA reads and A600FE 04/05/07 mapping; the MP evdev FD controls whether the kernel wants mapping. Its behavior may **race Dolphin**, but is **not inherently fatal**, as raw HID can still work with the kernel bound. [Core](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L411-L567), [reconciliation](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L1100-L1227), [MP FD](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-modules.c#L2771-L2835).

| Option | Cost | Impact on working references |
|---|---|---|
| **Keep kernel bound**, isolate test order | No elevated access; possible shared register resets | **Preserves** kernel, xwiimote and evtest acceptance; **recommended first** |
| Rebind *one device* to `hid-generic` | Needs privileged owner action; must verify the new binding and raw permissions | Loses that device's Wii kernel event interfaces, MotionPlus evdev and xwiimote |
| udev driver override or modprobe blacklist | Privileged/system policy; specific udev mechanism **not validated**; blacklist may apply broadly | Breaks or changes kernel Wii consumers; unsuitable default |
| Fixture-only different HID bus or PID, including D7 USB-UHID | Linux Wii driver matches BT bus 057e:0306/0330; alternate presentation must be separately tested | Not the same product acceptance; Dolphin HIDAPI name/ID/generic bind behavior can change |
| Dolphin input settings | Choose **ControllerInterface** native source and appropriate scanning/slots; no root | Does **not** unbind kernel or eliminate register contention |

## 4. Evidence limitations and final recommendation

**Independent corroboration:** WiiBrew describes active MotionPlus **A400FA identity and mode mapping**, not the F6/F8/F9 mirror or A40040 copy in the reviewed MotionPlus page. Dolphin's **own emulator** populates the F6/F8/F9 mirror from child FA identity and copies the child's calibration block from offset 20 **without reformatting** to its register offset 40. The reviewed Linux v6.12 driver does not use F6/40; previously merged Cemu evidence tests different reads. These are **Dolphin source-backed compatibility behaviors**, not physical hardware findings. [Emulated registers](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/Core/HW/WiimoteEmu/MotionPlus.h#L185-L242), [copy](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/Core/HW/WiimoteEmu/MotionPlus.cpp#L430-L465).

**Approve P0 → P1 → conditionally P2**, with narrow tests and a separate code PR under owner control. Keep kernel-driver remediation at P4 pending actual interference evidence. Do not invent calibration, promise physical Wii parity, imply native Dolphin 2503 source identity, or treat PR #45's unmerged results as merged acceptance.

**Open questions:** retail F7 meaning and hardware F6/40 behavior, different MotionPlus generations, exact installed Dolphin 2503 sequencing, which actor resets active mapping, and whether passing F6 and MP calibration yields continuous decoded gyro with Nunchuk. Only independent host traces can settle those. All proposed tests remain **not run** in this research task; previous Wii W-series records, virtualgamepad and hardware remain untouched.

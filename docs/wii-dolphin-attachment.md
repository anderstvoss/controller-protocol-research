# Dolphin Wii Remote attachment and MotionPlus gyro — decision brief

**Decision for Anders (source review, 2026-10-27).** **First keep `hid-wiimote` bound and test the minimal, explicitly imported-data MotionPlus passthrough model: active `A400F6/4` (downstream ID mirror) followed by active `A40040/16` (downstream calibration cache).** Test each checkpoint separately in the owned host before any Linux driver-binding change. The current model already supports the earlier high-value calibration and speaker prerequisites; the unmerged [research PR #45](https://github.com/anderstvoss/controller-protocol-research/pull/45) reports an MP-only Dolphin mapping-view gyro result, but its W8 evidence is **not** part of the `b550600` baseline and must not be promoted. This is a **software/virtual-host** decision, not a physical Wii compatibility claim.

**Source pins and scope.** Dolphin [master `3eb30c7620b4475b2e0404228ba0d2b238a132f1`](https://github.com/dolphin-emu/dolphin/tree/3eb30c7620b4475b2e0404228ba0d2b238a132f1), GPL-2.0-or-later; Linux `hid-wiimote` [v6.12](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L411-L567), GPL-2.0-only; `virtualgamepad` [main `5a11e507ac973c23ca10beb36edb44fc35034376`](https://github.com/anderstvoss/virtualgamepad/blob/5a11e507ac973c23ca10beb36edb44fc35034376/crates/gr-curated-controllers/src/wii_remote/memory.rs#L114-L210), AGPL-3.0; existing [WiiBrew MotionPlus oldid 120079](https://wiibrew.org/w/index.php?title=Wiimote/Extension_Controllers/Wii_Motion_Plus&oldid=120079), community documentation, unverified retail applicability. Existing source-only records `wii-gap-dolphin-controllerinterface-motionplus-calibration-gate`, `wii-gap-dolphin-emulated-motionplus-modes-passthrough`, `wii-gap-dolphin-hidapi-kernel-binding-competition`, `wii-gap-extension-calibration-checksum-unknown` and `wii-gap-wiibrew-motionplus-deactivation` remain intact. Native Dolphin **2503 ARM64** is reported to connect to the owned `BUS_BLUETOOTH` UHID `057e:0306`; **this cloud research did not inspect 2503's binary, perform a new host run, or prove exact 2503/master behavioral identity**.

### MP-only versus MP+Nunchuk: exact conditional sequence

- **MP alone:** status (no accessory) → LEDs ACK → 0x37 ACK → EEPROM 0016/8 → complete IR → mute/disable speaker → inactive MP A600FE/1 poll → A600F0=55 → A600FE desired-mode write (often 05 as default) → status/2-second settling and A400FA mode identification → **A40020/32** MP calibration → consume 0x37 gyro. **No A400F6 or A40040 is mandated without the downstream-connectivity flag.** Reported unmerged W8/PR #45 MP-only UI gyro is consistent, but not promoted to baseline.
- **MP+Nunchuk:** same initial gates → initial normal-extension **A400FB=00, A400FA/6** as applicable → determine desired Nunchuk mode **05** → A600FE activation/mapping → recheck active MP A400FA and embedded downstream-connected bit → **A400F6/4** mirrored Nunchuk ID → mode 05 confirmed (possibly after another transition/wait) → **A40020/32** MP calibration → **A40040/16** downstream Nunchuk calibration → 0x37 alternating gyro/Nunchuk packets. Status changes or another kernel reset can reorder/repeat earlier stages; this is **not** a single guaranteed linear trace.

### What F6 and 40 mean — and what is *not* verified

- **A400FA** identifies the **active MotionPlus itself** (and mode 04/05/07). **A400F6/4** supplies **mirrored downstream extension identity** in Dolphin's model: F6 = downstream ID byte 4, F8 = byte 0, F9 = byte 5, F7 is state information. Dolphin's emulator copies it after querying the child [emulated register layout](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/Core/HW/WiimoteEmu/MotionPlus.h#L184-L240), [copy action](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/Core/HW/WiimoteEmu/MotionPlus.cpp#L430-L465). Current [WiiBrew MP documentation](https://wiibrew.org/wiki/Wiimote/Extension_Controllers/Wii_Motion_Plus) documents A400FA activation, mode mapping and report bit packing **but was not found to specify the F6/F8/F9 mirror**. No independent retail read of F6 bytes was verified.
- **A40040/16** in Dolphin's emulated MotionPlus is a **byte-for-byte cache of the 16 bytes read from the downstream accessory's 0x20 register**, not a newly computed format; Dolphin's ControllerInterface expects those bytes and checks their two-byte checksum [emulation copy](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/Core/HW/WiimoteEmu/MotionPlus.cpp#L445-L464), [consumer](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L606-L655). WiiBrew MotionPlus documentation and the reviewed Linux v6.12 core **do not document/read this exact 40 copy**. Earlier independent rnconrad evidence of normal downstream 0x20 and 0x30 calibration templates (`wii-gap-extension-calibration-checksum-unknown`) does not itself establish physical 0x40 forwarding.
- **Kernel comparison:** reviewed `hid-wiimote` uses A400FA and A600FA and mode FE but no F6/40 reads in its core path [Linux](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L411-L567). Earlier Cemu source/test observations concern regular FA identity and A40020, **not** independent F6 or A40040 verification. Treat this as a **Dolphin-specific emulation/consumer convention** until corroborated elsewhere. No fabricated real-hardware or checksum claim.

## 3. Linux kernel-binding competition: options and costs

The pinned Linux `hid-wiimote` hotplug worker sends **A400F0=55, A400FB=00, A600F0=55, A600FB=00**, checks **A600FA and A400FA** then maps MP with **A600FE=04/05/07** when its `MP_USED` state requires it; opening/closing the dedicated MP evdev node changes that state. On status/extension/MP event it can re-run reconciliation and resend reports. Dolphin may be mid-read, awaiting an ACK, or waiting for its own mode to stabilize. This is a **race/shared ownership**, not evidence that the driver *always* makes Dolphin fail. [Kernel reset/map](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L411-L567), [hotplug worker](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L1100-L1227), [MP FD hooks](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-modules.c#L2771-L2835), [Dolphin warning](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/Core/HW/WiimoteReal/IOhidapi.cpp#L17-L59).

| Option | Mechanism / privilege | Dolphin trade-off | Kernel, xwiimote, evtest trade-off |
|---|---|---|---|
| **Keep existing binding; control test order** | No root. Compare no-holder and MP-evdev-holder, record exact event ordering. | Smallest intervention, mixed writes still possible. | **All kernel consumers remain usable. Preferred first.** |
| **Per-device unbind `wiimote`, bind `hid-generic`** | Kernel sysfs driver actions require elevated privilege and explicit owner approval. | **udev driver override / per-device bind rule** | Privileged persistent or session-scoped host policy; distro-specific support **not verified here**. | Potential selective isolation after enumeration/rule ordering; risks altered permissions and cold-plug behavior. | Same per-device loss of Wii kernel event interfaces while applied. |
| **modprobe blacklist / omit `hid_wiimote` module** | System-wide host policy, potentially requires root/reboot; modprobe blacklisting does not prove driver cannot be loaded explicitly. | Cleaner raw ownership if generic driver claims device, but host-wide blast radius. | **All** affected Wii kernel/xwiimote clients lose specialized mapping; unacceptable as default. |
| **Fixture-only nonmatching HID bus or product ID** | Code/test-presentation variation; Linux v6.12 `hid-wiimote` matches **Bluetooth-bus** `057e:0306` and `057e:0330` [table](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L1866-L1892). The [W7 Cemu merged evidence](https://github.com/anderstvoss/controller-protocol-research/pull/42) corroborates **raw transport** with `hid-wiimote` present, including repeated kernel/Cemu init/map transactions and the then-refused **A400FA/6** identity in MP arms. It is **not** proof of exclusive contention or a Dolphin-specific protocol defect. Subsequent proposed W8 evidence in unmerged [PR #45](https://github.com/anderstvoss/controller-protocol-research/pull/45) changes the acceptance picture: MP-only native Dolphin gyro is provisionally reported as responsive, while the MP+Nunchuk read A400F6/4 errors 7. Keep those claims separate until merged.

## 4. Recommended decision and unresolved questions

**Authorize a narrow owner-reviewed model change for the F6 downstream-ID mirror, then the 40 calibration copy only when the F6 gate is cleared and the corresponding calibration is actually imported.** Keep normal `A400FA`, `A40020`, the existing 04/05/07 data packet formats, error-7 boundaries, W5/W7 evidence and all physical claims unchanged. Do not add `F2` or arbitrary register defaults just to make Dolphin progress. The current [model read whitelist](https://github.com/anderstvoss/virtualgamepad/blob/5a11e507ac973c23ca10beb36edb44fc35034376/crates/gr-curated-controllers/src/wii_remote/memory.rs#L239-L306) and [write/IR camera admission](https://github.com/anderstvoss/virtualgamepad/blob/5a11e507ac973c23ca10beb36edb44fc35034376/crates/gr-curated-controllers/src/wii_remote/memory.rs#L118-L208) make the gap concrete.

Unresolved: (1) exact register values/semantics of F7 and whether physical external/integrated Plus revisions really mirror F6/F8/F9; (2) independent real-hardware proof of A40040 copy and source checksum correctness; (3) Dolphin 2503 versus pinned master differences; (4) status-event/MP-evdev contention frequency and who triggers each reset; (5) whether successful F6 and MP calibration yield continuously changing ControllerInterface gyro with Nunchuk or another gate emerges; (6) the outcome of PR #45 review/merge. Require distinct **discovery**, **ControllerInterface task progression**, **calibration present**, **report reception**, and **numeric decoded gyro** evidence at every checkpoint.

**All suggested host tests are not run as part of this cloud survey.** No local host changes, model modifications, privileged operations, serials/MACs, GPL source excerpts, or copied upstream prose were published. Existing `wii-w*-*` and `wii-c5-*` records are untouched. The identified kernel/Dolphin differences describe **competing consumer state policies**, not contradictory protocol facts, so no unsupported reciprocal `conflicts_with` edges were added; retain and link the prior claims rather than overwriting them.

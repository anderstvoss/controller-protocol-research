# Wii MotionPlus consumer comparison — Dolphin F6/40 versus other paths

**Purpose.** Establish which software consumers actually require the active-MotionPlus `A400F6/4` downstream identity mirror and `A40040/16` downstream-calibration copy, and distinguish those *consumer gates* from alleged physical Wii Remote protocol truths. This is an independently reviewable **source-only** supplement to [Dolphin's attachment decision brief](https://github.com/anderstvoss/controller-protocol-research/blob/77dad7408cbdb9d3738059de85e6f366eeabce59/docs/wii-dolphin-attachment.md), not an implementation mandate, new host experiment, physical readback, or evidence that those registers are absent from retail hardware.

**Baseline and pins.** Research main `77dad7408cbdb9d3738059de85e6f366eeabce59`, including merged [W8 PR #45](https://github.com/anderstvoss/controller-protocol-research/pull/45) and [Dolphin PR #46](https://github.com/anderstvoss/controller-protocol-research/pull/46). Cemu `29f2f1fae4631e2317977debd9eacd55cc28dd7d` (MPL-2.0), Dolphin `3eb30c7620b4475b2e0404228ba0d2b238a132f1` (GPL-2.0-or-later), wiiuse `e769bd73860a4f941bd110ebae5a790f968b71e3` (GPL-3.0-or-later), CWiid `fadf11e89b579bcc0336a0692ac15c93785f3f82` (GPL-2.0-or-later), Linux `v6.12`, SDL `877399b2b2cf21e67554ed9046410f268ce1d1b2`, xwiimote `4df713d9037d814cc0c64197f69e5c78d55caaf1`, RetroArch `1bbd7eda123acea17cbea15de48bea4fdb21a68d`. Every code link below pins revision and line range; GPL implementation is paraphrased, never excerpted.

**Reading limits:** Absence of F6/40 accesses in a *selected implementation path* does not prove registers do not exist on hardware. Source-level capability or a decoder function's presence does not establish complete native runtime acceptance. Linux `hid-wiimote`, SDL, xwiimote and RetroArch are not four independent physical-wire protocol decoders; they may share decoded kernel state or input semantics.

## New Cemu-specific result: a raw MP decoder exists, but appears unreachable

1. Cemu stores MotionPlus as separate `optional<MotionPlusData>`; its `m_extension` is **only** a variant of `monostate`, `NunchuckData`, and `ClassicData`. [state type](https://github.com/cemu-project/Cemu/blob/29f2f1fae4631e2317977debd9eacd55cc28dd7d/src/input/api/Wiimote/WiimoteControllerProvider.h#L43-L73)
2. The report-`0x37` parser includes a lambda accepting `MotionPlusData&` but visits **`m_extension`**, not `m_motion_plus`. Consequently that lambda has no selectable alternative in the pinned type. The presence of raw extraction logic is **not** evidence that this branch runs. [decoder/dispatch](https://github.com/cemu-project/Cemu/blob/29f2f1fae4631e2317977debd9eacd55cc28dd7d/src/input/api/Wiimote/WiimoteControllerProvider.cpp#L492-L550)
3. The reader then builds its externally supplied `MotionSample` with acceleration and jerk-like change, but **zero-valued angular/sensor arrays** rather than the `m_motion_plus` orientation. The native controller getter forwards that sample. [sample construction](https://github.com/cemu-project/Cemu/blob/29f2f1fae4631e2317977debd9eacd55cc28dd7d/src/input/api/Wiimote/WiimoteControllerProvider.cpp#L675-L719), [getter](https://github.com/cemu-project/Cemu/blob/29f2f1fae4631e2317977debd9eacd55cc28dd7d/src/input/api/Wiimote/NativeWiimoteController.cpp#L128-L142).

**Interpretation:** This is a **source-derived, pinned-version implementation limitation** on Cemu's normal exported gyro path. It strengthens the prior corpus's incomplete-MP-calibration caveat; it does **not** establish that all Cemu builds, alternate consumers or future revisions cannot produce gyro. It also explains why fixing F6/40 in virtualgamepad should **not** be expected to resolve Cemu's own motion-processing limitation.

**Independent protocol comparison:** wiiuse uses first qualifying gyro samples for zero reference, kernel evdev exposes raw-like gyro axes, SDL uses fixed slow/fast factors, while Dolphin uses its loaded 32-byte MP factory calibration as a gated rate-decoding input. These are different accuracy/normalization contracts, not evidence of contradictory physical gyro fields. [wiiuse gyro](https://github.com/wiiuse/wiiuse/blob/e769bd73860a4f941bd110ebae5a790f968b71e3/src/motion_plus.c#L251-L370), [kernel](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-modules.c#L2712-L2770), [SDL](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L1206-L1244), [Dolphin](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L574-L604).

## Current host evidence — W8 is merged; do not misstate it

The earlier [W8 results](https://github.com/anderstvoss/controller-protocol-research/blob/77dad7408cbdb9d3738059de85e6f366eeabce59/docs/wii-w8-consumer-runs.md) are *existing owned virtual-host tests*; no additional test was run for this PR.

- **Dolphin MP-only with imported calibration:** native 2503 ControllerInterface mapping view shows responsive gyro indicator as well as buttons, accel and basic IR; not verified physical rates or console-game acceptance.
- **Dolphin MP+Nunchuk:** 12,128 `A400F6/4` requests returned error 7 before Dolphin reached MP calibration. No assertion of zero physical gyro.
- **Cemu MP+Nunchuk clean follow-up:** 18 successful `A40020/16` reads (17 replies matching imported Nunchuk calibration, one matching the first half of imported MP calibration); interpreted application calibration and decoded gyro **unobserved**. This shows mapped/unmapped bank exposure, not definitive consumer misbinding.
- **Cemu MP-only:** repeated status/identity requests and unresolved motion state retention; decoded application gyro **unobserved**. In clean comparison the Cemu setup loops could follow successful acknowledgements, not necessarily a rejected request; kernel and Cemu writers were not uniquely attributable.

Avoid combining the W8 record's *observed data delivery* with this PR's *static Cemu reachability diagnosis* as if the application itself had been instrumented. Existing W8 experiments remain unchanged.

## Does the cross-consumer evidence alter the F6/40 provenance classification?

**It narrows necessity, not hardware truth.** The existing [Dolphin provenance brief](https://github.com/anderstvoss/controller-protocol-research/blob/77dad7408cbdb9d3738059de85e6f366eeabce59/docs/wii-dolphin-attachment.md) places F6 as a **Category 1–leaning, low-to-moderate confidence** hardware-derived hypothesis and the `0x40` cache as a **Category 2–leaning, moderate confidence** compatibility representation of real calibration needs. The independent consumers confirm that **neither register read is a universal software prerequisite for raw MP decoding**. They do not resolve whether a physical external/integrated MotionPlus exposes both addresses and precisely what F7/40 contains. No conflicting physical claims or reciprocal `conflicts_with` edges are justified.

This matters for the memory model: Dolphin `F6/4` is an explicitly consumer-defined *identity* gate, and Dolphin `40/16` follows MP `20/32` as an accessory calibration request; Cemu's `20/16` is **the same address window but not necessarily the same bank** once MP mapping changes. Keep normal and mapped register bank semantics scoped; do not invent factory bytes or indiscriminately alias 20/40.

## Coordinator / next lab decision (all proposed tests unrun here)

1. Keep `hid-wiimote` bound; reproduce **Dolphin MP-only** as positive control, logging actual decoded gyro.
2. For **Dolphin MP+Nunchuk**, implement (only in separate authorized virtualgamepad work) bounded imported-data F6 identity mirror first; confirm next request before conditional 40 block. Require fresh host traces and no regression in MP-only or kernel evdev.
3. For **Cemu**, use a *separate* application-side oracle: distinguish FA/20 read/reply, stable selected extension, live gyro decode dispatch, and exported motion sample. No amount of F6/40 support establishes Cemu gyro without addressing its pinned source-path gap.
4. Compare with wiiuse/CWiid **only if a genuine L2CAP transport is added**; otherwise use them as source references, not false runtime failures. Validate xwiimote/SDL/RetroArch only at their appropriate kernel or evdev layers.
5. A physical external MP+Nunchuk experiment would directly compare inactive child's FA/6 and 20/16 to active MP's F6/4 and 40/16 on the same revision; do not claim this was run.

## Transport and host identity

The proposed direct Bluetooth identity is Valve **28de:1303**. Pinned Linux v7.3 `hid-steam` matches it on the Bluetooth HID bus and uses its IBEX decoder; unlike a receiver, it does not need USB slot-interface numbers. BlueZ's HID-over-GATT (HOGP) client constructs a `BUS_BLUETOOTH` UHID device from the discovered Report Map, PnP identity, and HID Report characteristics. This is a *host presentation*, not Bluetooth advertising or pairing. Evidence: [steam-ble-kernel-v73-binding](https://github.com/anderstvoss/controller-protocol-research/blob/ce6b8d3b70fd0957135eb921ef6098988f355cb1/records/claim/steam-ble-kernel-v73-binding.json), [steam-ble-bluez-hogp-path](https://github.com/anderstvoss/controller-protocol-research/blob/ce6b8d3b70fd0957135eb921ef6098988f355cb1/records/claim/steam-ble-bluez-hogp-path.json), [steam-ble-bluez-identity](https://github.com/anderstvoss/controller-protocol-research/blob/ce6b8d3b70fd0957135eb921ef6098988f355cb1/records/claim/steam-ble-bluez-identity.json).

## Report, feature and output contracts

- Kernel IBEX expects native input IDs `0x42` (54 bytes), `0x45` (46), battery `0x43` (15), and connection state `0x79` (2). SDL Triton also parses `0x47`; neither decoder establishes which reports retail BLE firmware sends. [steam-ble-kernel-v73-input](https://github.com/anderstvoss/controller-protocol-research/blob/ce6b8d3b70fd0957135eb921ef6098988f355cb1/records/claim/steam-ble-kernel-v73-input.json), [steam-ble-sdl-triton-reports-and-output](https://github.com/anderstvoss/controller-protocol-research/blob/ce6b8d3b70fd0957135eb921ef6098988f355cb1/records/claim/steam-ble-sdl-triton-reports-and-output.json).
- Kernel/SDL send HID feature requests, settings and lizard-mode writes. BlueZ maps numbered UHID feature GET/SET to GATT Report-characteristic reads/writes, removing the report-ID prefix on SET and restoring it on GET. The characteristic layout and real responses remain unmeasured. [steam-ble-bluez-feature-routing](https://github.com/anderstvoss/controller-protocol-research/blob/ce6b8d3b70fd0957135eb921ef6098988f355cb1/records/claim/steam-ble-bluez-feature-routing.json), [steam-ble-kernel-v73-feature-lifecycle](https://github.com/anderstvoss/controller-protocol-research/blob/ce6b8d3b70fd0957135eb921ef6098988f355cb1/records/claim/steam-ble-kernel-v73-feature-lifecycle.json).
- BlueZ's examined SET_REPORT path uses an ordinary ATT write, not its long-write procedure. **Conditional**: a complete 64-byte numbered feature report would carry 63 data bytes and require ATT MTU at least **66**. This is a transport constraint, **not** an observed pairing MTU or proof that full-length reports are sent over BLE. [steam-ble-bluez-att-mtu-feature-constraint](https://github.com/anderstvoss/controller-protocol-research/blob/ce6b8d3b70fd0957135eb921ef6098988f355cb1/records/claim/steam-ble-bluez-att-mtu-feature-constraint.json).
- SDL versions are not behaviorally identical: the later pinned Triton source dispatches left/right digital trigger clicks and supports additional short haptic-effect writes not handled by the earlier D9 SDL build. Missing buttons or effect delivery in that older build cannot alone establish a protocol bug. [steam-ble-sdl-private-vs-upstream-delta](https://github.com/anderstvoss/controller-protocol-research/blob/ce6b8d3b70fd0957135eb921ef6098988f355cb1/records/claim/steam-ble-sdl-private-vs-upstream-delta.json).

## Acceptance boundaries

A locally fabricated `linux.uhid.bluetooth` device may be valuable for probing kernel binding and SDL input, but **must not be called a paired Bluetooth controller**. The BLE Report Map, firmware behavior, feature responses, physical cadence, Steam Input acceptance, output/LED/haptic effects and radio state are not yet validated. A wired report descriptor or an OpenPuck receiver interface is not a substitute. [steam-ble-bluez-att-mtu-feature-constraint](https://github.com/anderstvoss/controller-protocol-research/blob/ce6b8d3b70fd0957135eb921ef6098988f355cb1/records/claim/steam-ble-bluez-att-mtu-feature-constraint.json), [steam-ble-sdl-private-vs-upstream-delta](https://github.com/anderstvoss/controller-protocol-research/blob/ce6b8d3b70fd0957135eb921ef6098988f355cb1/records/claim/steam-ble-sdl-private-vs-upstream-delta.json).

For the owner-only pairing procedure, private-data rules, D9 capture order and UHID acceptance gates, consult [steam-controller-2026-ble-source-and-d9-plan.md](https://github.com/anderstvoss/controller-protocol-research/blob/ce6b8d3b70fd0957135eb921ef6098988f355cb1/docs/steam-controller-2026-ble-source-and-d9-plan.md). Those are proposed tests, **not results**.

## Ownership timeline and plausible races

1. **Probe:** Linux hid-playstation uses kernel-owned HID GET feature requests. DualSense `0x09` pairing, `0x20` firmware, `0x05` calibration must succeed or Linux probe aborts (`hid-playstation.c` 1023–1147, 1150–1204, 1783–1835; `ds-l0-consumer-probe-feature-failure-tolerance`). DS4 USB pairing `0x12`, calibration `0x02` and version `0xA3` have different failure semantics; firmware `0xA3` is optional on newer driver but fatal on older `hid-sony` (`hid-playstation.c` 1938–2175, 2791–2805; `ds4-l0-consumer-kernel-a3-optional`, `ds4-l0-consumer-hidsony-a3-probe-gate`). **Host evidence**, not proof physical device supports every version.
2. **Kernel ownership after probe:** hid-playstation decodes input and drives Linux evdev, kernel FF/lightbar/player-LED and optional audio-related state; it emits output reports asynchronously from its own work/scheduling (`hid-playstation.c` 1251–1429, 2277–2386; `audio-linux-hid-playstation`). Its output writes can interleave with any raw HID client output, potentially replacing lightbar/rumble/trigger state. This is an **inferred contention hypothesis**: exact interleaving and hardware last-writer semantics are **No evidence**.
3. **SDL3 hidraw:** SDL PS5/PS4 HIDAPI independently requests feature reports, sets output valid flags, and sends LED/rumble/sensor enables (`SDL_hidapi_ps5.c` 418–457, 555–700; `SDL_hidapi_ps4.c` 462–647, 924–973). A hidraw handle does **not** automatically unbind the kernel driver; it may coexist with kernel's evdev and output work. SDL's calibration fallback is separate from Linux's (`ds-l0-sdl-calibration-fallback`, `ds4-l0-consumer-sdl-calibration-fallback`).
4. **Steam Input:** only public udev rules establish suggested raw-node access (`steam-client-udev-60-steam-input`); which private reports/feature calls Steam issues and whether it disables the kernel output owner are **No evidence**. Do not claim that Steam's own output path wins.
5. **Wine/Proton:** public `winebus.sys/main.c` (commit `66caeb4`, lines 395–403, 501+) chooses hidraw or evdev and applies BT raw report fixups for Sony. Actual selected backend and multi-open arbitration on Anders's host are **No evidence**. Raw and evdev are separate paths, not a universal assertion of exclusivity.

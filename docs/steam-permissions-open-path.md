## 1. Exact public udev rules that may touch Valve 2026 devices

The inspected V rules use **vendor-wide matches**; no distinct `28de:1302`, `1303`, `1304` or `1305` PID-specific grant occurs in the reviewed first 17 lines. The following are conditional on the resulting **udev ancestry and actual node**, not a guarantee that every transport has every node. `MODE="0660"` grants owner/group rw; `TAG+="uaccess"` asks the system's seat-access mechanism for active-user ACLs, where supported.

| V line | udev match/action | 1302 wired | 1303 BLE | 1304 Puck / 1305 receiver | #258 privilege / persistence / risk / suggested release default |
| --- | --- | --- | --- | --- | --- |

**Not granted by V:** no direct `/dev/uhid` permission rule in these lines, no explicit per-virtual-controller USB ancestry fabrication, no privilege to rebind the kernel HID driver. Root is needed for installing/removing the rules and privileged driver-binding changes. Rule presence, `uaccess` runtime ACLs and sandbox/Flatpak policy are **No evidence** on an actual host. The `uinput` grant is more powerful than a plain gamepad read operation.

**Calibration check:** Neither the inspected **direct 1302** kernel registration path nor SDL3 Triton initialization performs a separate IMU or trackpad calibration GET/read in the reviewed methods. The kernel's GET attributes (0x83) can change **sensor interval** and must not be relabelled factory calibration. This is a bounded absence in these consumers, **not** proof physical device has no calibration, nor that other Steam client code ignores it. No firmware constants or returned physical serial formats have been measured.

## 3. Step-16 and #258 lab plan (all **not run**)

1. Preflight under a normal active user: record `udevadm info` *sanitized attributes only*, matching rule numbers, `stat` ACL/mode, `getfacl` sanitized, selected HID bus, actual hidraw/event/`uinput`/`uhid` access; distinguish current seat grants from group privileges. Check vendor-wide rule side effects on **unrelated** Valve devices before recommending installation.
2. With `hid-steam` bound, trace *virtual-host* feature exchange return codes at kernel registration: serial `0xae` success, absent, malformed; `0x83` normal, empty, malformed; assert whether device still creates evdev nodes (per source, GET errors should be tolerated). Separately fail physical HID start, synthetic client creation and event registration to confirm actual gates.
3. SDL direct `1302` with kernel bound/unbound: deny/open hidraw, attempt lizard SET failure/short write, sensor enable success/fail, `0x80` output success/fail; check whether joystick remains enumerated and controls decode. Avoid granting `uinput` merely to make SDL read raw HID.
4. Test portability: seat user login/logout, multiple user sessions, headless service, packaged sandbox and local **per-device** permissions; log only sanitized outcomes. Test uninstall/reversibility and no persistence after policy uninstall. Driver rebind needs separate explicit owner authorization.
5. For final #258 disposition, record each grant's necessary user-facing install step, scope, security side effects and the preferred least-privilege default. **No production release permission default is qualified by this source review alone.**

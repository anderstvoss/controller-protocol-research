# Steam Controller 2026 / Puck — earlier research gap audit

**Verification tier:** source-reviewed only (15 October 2026). No hardware, host kernel, Steam client, USB analyzer, SDL runtime, or physical capture was available to this lane. This is not a controller implementation or an acceptance result. This audit is preparation for [virtualgamepad #159](https://github.com/anderstvoss/virtualgamepad/issues/159), its separate source-ledger lane [#167](https://github.com/anderstvoss/virtualgamepad/issues/167), and later step 16. It does not claim to complete a step on #176.

## Executive findings

Earlier work was directionally right that a Puck must be treated as a stateful, multi-interface receiver, that wired and wireless input reports cannot be treated as the same 0x45-only channel, and that host-to-device capture is essential for feedback. It was **not** right to present OpenPuck's unrecovered historical 28de:1142 identity as the identity of its currently inspected 29f4d1e implementation: that revision uses 28de:1304. The old physical-Puck report of 28de:1304 is compatible with current source IDs but its original capture remains **missing**, so it cannot be promoted to physically observed. The OpenPuck four-HID-interface compatibility implementation is not a verified representation of the physical Puck's USB composite device: the pinned kernel source describes seven interfaces, two of which are non-HID, four of which are controller slots, and one pogo interface. The 2015 Steam Controller is out of scope.

**Biggest gaps blocking a gameplay-first 2026 direct-wired realization (ranked):**

1. **Playable input map:** independent neutral/edge report fixtures for 0x42 and 0x45 (and 0x47 when used), exact report lengths, field offsets, both sticks, triggers, all native buttons/paddles, both trackpads, touch/grip capacitive bits, pressure, IMU and timestamp. Kernel/SDL source parsing exists, but independent physical/virtual differential evidence does not.
2. **Feature/probe exchange:** physical or host-visible descriptor and GET/SET feature 1/2 transactions, configuration and mode transitions (including IMU and lizard), with success/error replies and retry behavior. Pure host parsers do not establish a complete emulated protocol.
3. **Haptics and feedback:** correctly addressed 0x80+ output reports, 0x44 acknowledgement/flow-control semantics, buffered streaming modes (0x86–0x89), and reverse output/host writes. The Steam-active experiment's missing host-output side is the critical artifact.
4. **Lizard/desktop presentation:** prove on/off, host-alive refresh, watchdog, 0x40/0x41 keyboard/pointer and native-input suppression without confusing an explicit companion session with a transport realization. SDL's 3 s refresh and OpenPuck's approximate 7 s watchdog are software behaviors, not physical timings.
5. **Direct USB/HID and actual consumer readiness:** capture the wired USB descriptor/identity and the consumer probe sequence, then perform native Linux/SDL/Steam recognition, lifetime, outputs and removal testing. Pinned source suggests direct UHID might suffice for a playable tier, but this is not a live result; Puck USB equivalence is a separate #168 question.

**Named, unrecovered artifacts (do not treat as present or search anew in this lane):** EXP-SC2-PUCK-USB-20260731 physical Puck USB capture; Steam-active haptics experiment including host→device traffic; HHD Steam Controller 2026 source review; the historical OpenPuck revision reportedly using 28de:1142. Earlier searches of the old corpus, alpha-lab-archive, GamepadRouter, GamepadManager and gamepadcapture did not recover them ([#159 earlier-research audit](https://github.com/anderstvoss/virtualgamepad/issues/159#issuecomment-6163651567)). GamepadRouter templates have placeholder IDs only. The virtualgamepad wip/btvirt branch is reference-only, not SC2 evidence ([#159](https://github.com/anderstvoss/virtualgamepad/issues/159#issuecomment-6167398581)).

## Needed lab/review artifacts and ownership

1. **For direct wired priority:** a fresh private 28de:1302 descriptor dump and paired source/consumer raw HID transcript with buttons, sticks, both trackpads, triggers, capsense and IMU activated individually; record firmware/host/kernel/version and exact report lengths. Existing source parsers are reference comparators, not the gold packet oracle.
2. **For GET/SET and lizard:** record only authorized test-device feature-report roundtrips, include negative/timeout tests, and observe 0x40/0x41 and gamepad reporting before/during/after mode changes. Do not claim OpenPuck's watchdog constant as hardware timing.
3. **For haptics:** measure host-to-device 0x80+ outputs concurrently with 0x44 status and physical actuator observations. Isolate streaming and conventional rumble; classify unknown reports without discarding them.
4. **For Puck later:** preserve and separately validate seven-interface USB topology, four receiver slots, independent per-slot connect/disconnect and output, 0x79 and 0x7b, pairing and bond lifetime. Never infer real USB enumeration from UHID BUS_USB metadata.
5. **For acceptance:** the local agent owns P1 on a qualified host after D9, Steam/SDL/hid-steam runtime results (#144/#159), and Rust/runtime functionality. This audit owns no controller source code or acceptance promotion.

# Wii MotionPlus: consumer paths, hardware generations, and W4/W5 discriminators

**W5 update:** [Research #35](https://github.com/anderstvoss/controller-protocol-research/pull/35) and [W5 gyro diagnosis](wii-w5-gyro-diagnosis.md) report valid H3 packets and changing kernel MotionPlus evdev gyro but zero SDL gyro events in holder/control arms; Dolphin direct-backend sanity remains blocked (no private cached-mode instrumentation or physical parity).

**Status:** source-only research addendum to [Wii gyro investigation](wii-gyro-investigation.md), not a new hardware or application acceptance result. Source pins: SDL 3.2.10 `877399b2b2cf21e67554ed9046410f268ce1d1b2`; Linux `v6.12` (and mainline `734bef548a96e8774d6eef5dfa2026c6edc4e80b` in parent document); Dolphin `e1d35f666cc35f6ead55d32ea2679df44d04da72`. Dolphin and Linux are GPL-licensed, so **only independently worded behavioral summaries and source/line locators** are published. No raw reports, upstream code/prose, host identities or private captures. The [existing W5 executing-agent brief](https://github.com/anderstvoss/virtualgamepad/issues/158#issuecomment-6373947878) controls physical runs, changes and merge boundaries.

## A. Identify the consumer before diagnosing zero gyro

| Consumer / setup | Endpoint exposed to application | Who attempts MotionPlus activation? | What counts as gyro success? |
| --- | --- | --- | --- |
| Linux evdev on `hid-wiimote` | Separate **Nintendo Wii Remote Motion Plus** input node exposing kernel decoded axes | Kernel's MotionPlus input **open** callback sets `MP_USED`, then kernel reconfiguration attempts mode mapping | Changing MotionPlus evdev `ABS_RX/RY/RZ` while held open |
| SDL 3.2.10 Wii **HIDAPI** | Native Wii HID reports via Linux **hidraw**; not the MotionPlus evdev node | On **Linux**, SDL omits A600FE activation and assumes kernel maintains state; SDL still sends extension reset commands | SDL sensor registered **and enabled**, active mode cached, valid gyro-marked extension data, changing SDL gyro events |
| SDL default Linux **evdev** fallback | Kernel-normalized generic Wii input controls | Kernel if MotionPlus evdev node opened by someone; SDL's core evdev claim alone is not proof it opens the MP node | Do **not** infer Wii gyro HIDAPI acceptance from base buttons/axes |
| Dolphin **Real Wii Remote** with emulated Bluetooth stack | Real HID reports forwarded from Bluetooth L2CAP or a compatible HIDAPI backend to emulated console Bluetooth | Wii game/console protocol generally controls register state; real-Wiimote transport itself is not an SDL gyro sensor API | Game sees working Wii motion controls; does not by itself establish a ControllerInterface gyro reading |
| Dolphin **ControllerInterface** using a physical Wii Remote as generic emulated-controller input | Dolphin's own real-Wiimote input decoding | **Dolphin**, through identity polling, mode writes, recheck/wait and calibration reads | Calibrated changing MotionPlus gyro values in Dolphin's ControllerInterface |
| Dolphin **Bluetooth adapter passthrough** | Real Bluetooth adapter routed to emulated Wii | Wii software through passed-through adapter | Requires suitable Bluetooth topology; a synthetic UHID `BUS_BLUETOOTH` identity is **not** the same |
| Dolphin fully **emulated Wii Remote** | Dolphin synthesizes the Wii MotionPlus peripheral and HID stream from its own input assignments | Dolphin's emulated Wii/peripheral logic | Application-facing Wii protocol emulation; not an independent physical reference |

Source anchors: [SDL Wii enable/HID match](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L174-L197), [SDL raw HID reads](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L197-L225), [kernel MP open/close](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-modules.c#L2771-L2795), [Dolphin real Linux Bluetooth sockets](https://github.com/dolphin-emu/dolphin/blob/e1d35f666cc35f6ead55d32ea2679df44d04da72/Source/Core/Core/HW/WiimoteReal/IOLinux.cpp#L286-L336), [Dolphin HIDAPI read/write](https://github.com/dolphin-emu/dolphin/blob/e1d35f666cc35f6ead55d32ea2679df44d04da72/Source/Core/Core/HW/WiimoteReal/IOhidapi.cpp#L149-L205), [Dolphin real report forwarding](https://github.com/dolphin-emu/dolphin/blob/e1d35f666cc35f6ead55d32ea2679df44d04da72/Source/Core/Core/HW/WiimoteReal/WiimoteReal.cpp#L450-L479).

**Driver expectation, precisely:** SDL does **not** test that `hid-wiimote` is bound as a hard opening precondition; it can reach hidraw if the OS exposes it. But its *Linux-only MotionPlus activation behavior* delegates to the kernel and is therefore sensitive to the binding and to whether anyone opens the MP evdev node. Dolphin's direct HIDAPI backend, in contrast, [warns about `hid-wiimote` contention and prefers `hid-generic`](https://github.com/dolphin-emu/dolphin/blob/e1d35f666cc35f6ead55d32ea2679df44d04da72/Source/Core/Core/HW/WiimoteReal/IOhidapi.cpp#L17-L59) for its independently managed Wii protocol interactions. **This is not authorization to unbind a driver or change host policy**; record binding and make any disruptive host setup an owner decision.

## B. Hardware personalities: distinguish four cases, not two

| Virtual/physical personality to reason about | Bluetooth/host classifier | MotionPlus hardware | Kernel discovery/activation implications | Gyro expected in SDL HIDAPI? |
| --- | --- | --- | --- | --- |
| Original **RVL-CNT-01**, no accessory | Gen10 / generally Nintendo `0x057e:0x0306` | **Absent** | External MP polling may run but no MP sensor to map | **No** gyro; base accelerometer is separate |
| Original RVL-CNT-01 + external MotionPlus attachment | Same **Gen10** identity; external accessory does not turn base Remote into a `-TR` | **Hot-pluggable extension** | Poll/detect external MP; creates MP input node if discovered; MP_USED open required for mapping | **Yes if active and valid** (but W4 zero remained blocked) |
| **Early integrated Wii Remote Plus** with old naming/ID conventions | Can be classified **Gen10** under `RVL-CNT-01` despite built-in sensor | **Built-in**, but older identity may not advertise built-in status | Driver may take external-discovery path even though actual sensor is not detachable | **Potentially**, under the same active-mode/packet conditions; actual variant ID/calibration remains **unknown** |
| Later **RVL-CNT-01-TR** Wii Remote Plus | Gen20 / generally `0x057e:0x0330` | **Built-in** | Kernel sets `BUILTIN_MP` and avoids external MotionPlus hotplug polling; does **not** exempt from active-mode mapping / MP_USED behavior | **Potentially**, if mapped at SDL open; nonzero not guaranteed by `-TR` identity |

Evidence: [Linux v6.12 generation/name/ID classification](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L818-L864), [module lists for Gen10 versus Gen20](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L582-L605), [kernel built-in MP flag](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-modules.c#L2630-L2664), [MP detection polling](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L899-L933). Existing research records **`wii-original-remote-consumer-revision`**, **`wii-tr-consumer-revision`** and **`wii-early-plus-revision-gap`** must remain as they are: name classification alone does not establish exact physical early integrated revision. Both external and integrated MotionPlus still use the same general extension-register/gyro-report design; never silently equate their identifiers, startup behavior, timing or calibration.

**SDL joystick class caveat:** the SDL Wii driver registers a gyro only for its base-Wii or Nunchuk classification when MotionPlus presence is detected. It does **not** register gyro in the Classic gamepad classification through the same path: [SDL OpenJoystick](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L773-L799). Thus even correct `0x07` Classic pass-through should not be interpreted as a failed SDL gyro acceptance test if no sensor is advertised.

## C. W4 observed values and why they do not diagnose the encoder

[W4 lab evidence](https://github.com/anderstvoss/controller-protocol-research/blob/main/docs/wii-w4-sdl-fixed-extension.md) recorded five fixed-before-open profiles, each with 60 s of retained SDL HIDAPI claim. In **MotionPlus alone** and **MotionPlus + Nunchuk**, SDL advertised/enabled gyro while all polled gyro values were zero. The upstream host drive changed 14-bit raw rotations `(9000,7000,8500)` and `(7000,9000,7800)`. This does not prove SDL ever dispatched gyro events, or whether the kernel activated MP.

### SDL's critical state transitions

1. `ReadExtensionControllerType` can encounter mapped MP and issue a reset before final extension identity classification: [677-709](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L677-L709).
2. `OpenJoystick` **unconditionally** calls `InitializeExtension` (and thus `SendExtensionReset`, A400F0=0x55) **before** `GetMotionPlusState`: [625-630](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L625-L630), [773-787](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L773-L787).
3. `GetMotionPlusState` distinguishes mapped MP **active mode** at A400FE from merely present but inactive MP at A600FE: [385-428](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L385-L428).
4. The Linux branch of `ActivateMotionPlusWithMode` **does not** write A600FE **or** set SDL's cached `m_ucMotionPlusMode`: [457-468](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L457-L468), [sensor-enable](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L860-L877). Disable still may deactivate through a reset: [483-492](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L483-L492).
5. SDL registers the gyro using **presence**, but dispatches actual samples only when **cached active mode** is nonzero, an extension segment of at least six bytes is available, the invalid flag is clear and byte 5 **bit 1** identifies a gyro (rather than pass-through) frame: [registration](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L789-L799), [dispatch](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L1266-L1299). `HandleMotionPlusData` converts 14-bit fields around neutral `8192` to radians/sec using slow/fast range flags: [1206-1243](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L1206-L1243).
6. The periodic presence check can notice attachment-state changes but does **not** update `m_ucMotionPlusMode` on ordinary already-present checks: [430-455](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L430-L455), [1396-1435](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L1396-L1435). A late kernel remap is not automatically SDL recovery.

The kernel **only maps MP if its hotplug worker's captured `MP_USED` flag is set**: [v6.12 1100–1195](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L1100-L1195). Since SDL's open reset can undo a mapping, **opening a MotionPlus evdev FD before SDL is a hypothesis, not a fix**; observe *both* kernel reactivation and SDL's cached mode when diagnosing H1/H4.

For the two W4 driven triples, if actual mapped gyro-marked packets reach SDL with **slow flags on all axes**, SDL's scaling would yield approximately `(-0.289,+0.758,-1.118)` and `(+0.368,-1.118,+0.758)` rad/s in SDL's output axis order. These are **conditional calculated targets only**; real measured data are still zero.

## D. What Dolphin independently confirms, and what it does not

Pinned [Dolphin ControllerInterface path](https://github.com/dolphin-emu/dolphin/blob/e1d35f666cc35f6ead55d32ea2679df44d04da72/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L449-L605) does **not** rely on SDL's Linux MotionPlus activation shortcut. It actively checks the mapped extension ID, distinguishes inactive from active, writes a desired mode (04, 05, 07), waits then rechecks ([1049-1070](https://github.com/dolphin-emu/dolphin/blob/e1d35f666cc35f6ead55d32ea2679df44d04da72/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L1049-L1070)). It reads MotionPlus calibration from active register offset 0x20 and [will not update decoded gyro state until calibration exists](https://github.com/dolphin-emu/dolphin/blob/e1d35f666cc35f6ead55d32ea2679df44d04da72/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L1462-L1470). This is **Dolphin-specific**: SDL 3.2.10 Wii HIDAPI applies fixed raw angular scaling without a MotionPlus calibration read. A Dolphin calibration failure cannot be silently projected onto the SDL W4 result.

Pinned [Dolphin emulated MotionPlus](https://github.com/dolphin-emu/dolphin/blob/e1d35f666cc35f6ead55d32ea2679df44d04da72/Source/Core/Core/HW/WiimoteEmu/MotionPlus.cpp#L190-L369) defines inactive/active I2C behavior, explicit activation/deactivation with delay, and [gyro/pass-through packet generation](https://github.com/dolphin-emu/dolphin/blob/e1d35f666cc35f6ead55d32ea2679df44d04da72/Source/Core/Core/HW/WiimoteEmu/MotionPlus.cpp#L600-L709) from the [six-byte data structure](https://github.com/dolphin-emu/dolphin/blob/e1d35f666cc35f6ead55d32ea2679df44d04da72/Source/Core/Core/HW/WiimoteEmu/MotionPlus.h#L77-L113). It is a **software compatibility model** and synthetic calibration source, not a retail physical capture. Compare any proposed virtualgamepad packet fix against WiiBrew `wii-gap-wiibrew-motionplus-*` records, not solely Dolphin emulator choices. Do not modify `wii-c5-*` or `wii-w*-*` records.

A Dolphin test must label one of: real console Bluetooth path; ControllerInterface direct input; or Dolphin's emulated Wii Remote. Merely selecting a Real Wii Remote inside Dolphin without recording the backend does not isolate gyro decoding, kernel-driver contention or pairing. The [raw HIDAPI backend's Linux warning](https://github.com/dolphin-emu/dolphin/blob/e1d35f666cc35f6ead55d32ea2679df44d04da72/Source/Core/Core/HW/WiimoteReal/IOhidapi.cpp#L17-L59) is relevant to *Dolphin's direct protocol ownership*, and contrasts with SDL's Linux reliance on kernel state.

## E. Follow-up tests and evidence boundaries

The [W5 implementing-agent brief](https://github.com/anderstvoss/virtualgamepad/issues/158#issuecomment-6373947878) governs execution and priority: **(1)** H3 pure packet validation and reference vectors, **(2)** independently changing kernel evdev `ABS_RX/RY/RZ` with held MP input FD, **(3)** controlled H1/H4 holder/no-holder SDL comparison with register actor attribution, **(4)** H2 alternate SDL version only if cheap. This addendum does not authorize a Dolphin host run, driver unbinding, root changes, production implementation changes, or research/code PR merges. Dolphin is a *separate optional acceptance axis* requiring owner approval and access-type-specific instrumentation.

The minimum decisive observations are: exact recorded host/kernel, model/identity, driver binding, owner-provided access authorization, native report mode and six-byte extension packets, kernel `MP_USED` holder lifetime, A400F0 reset and A600FE mapping writes with timestamp/source attribution, mapped ID **before and after** SDL reset and at `GetMotionPlusState`, variation in kernel evdev sensor values, SDL's registered+enabled status and actual gyro event **count/min/max**, process disconnects, and cleanup. Retain sensitive raw logs private. No current source evidence proves physical calibration, retail hardware equivalence, SDL 3.4.18 runtime acceptance, Steam internals or any W5 host outcome.

**Related new consumer claims:** `wii-gap-dolphin-hidapi-kernel-binding-competition`, `wii-gap-dolphin-real-remote-path-separation`, `wii-gap-dolphin-controllerinterface-motionplus-calibration-gate`, `wii-gap-dolphin-emulated-motionplus-modes-passthrough`; original Wii revision and W4/W5 records are unchanged.

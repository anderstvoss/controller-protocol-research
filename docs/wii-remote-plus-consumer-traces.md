# Decision brief — Wii Remote Plus consumer startup traces (TR / 057e:0330)

**Recommendation:** Authorize only a *creation-time, opt-in TR compatibility prototype*, not a physically faithful retail Wii Remote Plus claim. A valid Bluetooth-bus Nintendo `057e:0330` identity is necessary for discovery; a working implementation also needs status/ACK, inactive and mapped MotionPlus identity, report-mode coordination, gyro frames and conditional downstream attachment handling. Reuse the external MotionPlus codec only with **explicit compat labeling**. Preserve the owner-approved F6/40 shim flags. Never manufacture calibration, unknown full integrated identities or challenge bytes. Full software acceptance and separate hardware revision captures remain gates.

**Source boundary:** Based on research main `8aeab2ba524bbdab3c41f84ef35ba73909bd1ca0` (187 Wii claims); after merging main `658dca7` (W9e #55 and #57) the inventory is **203 Wii claims**, building on merged [#51](wii-remote-plus.md), [#46](wii-dolphin-attachment.md), [#47](wii-motionplus-consumer-comparison.md), [#49](wii-motionplus-challenge.md) and W9/compat evidence. Pinned Linux **v6.12**, SDL **877399b2b2cf**, Dolphin **3eb30c7620b4**, Cemu **29f2f1fae463**, wiiuse **e769bd73860a**, xwiimote **4df713d9037d**. **No host or hardware tests run.** These are *source-derived, conditional task/state-machine traces*, not deterministic packet captures. Report-mode, sensor-open, speaker/IR selection, status resets, and concurrent consumers can reorder or repeat requests. No GPL code or private device data is reproduced.

## Core wire vocabulary

- Output **0x15** status → input **0x20** status; the status extension bit **0x02** is **not** a universal internal-MotionPlus-present flag.
- Output **0x16** register write → input **0x22** ACK/error; output **0x17** register/EEPROM read → input **0x21** data/error and matching address/length. Output **0x12** selects a report ID, and corresponding core/accel/IR/extension data packets follow.
- Keep `A600` inactive MotionPlus and `A400` downstream/active-MP banks distinct. Do not accept a write ACK as equivalent to a successful read response. [Kernel request+handlers](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L240-L407), [status/read/ACK](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L1414-L1493).

## Q1. Startup transaction ladders, all three attachment cases

### Linux `hid-wiimote` — Gen 2, **kernel bound**

**Conditional order:** (1) Bluetooth-bus HID match and first **0x15→0x20** status. If status signals an extension, initialize **A400F0=55**, **A400FB=00**, read **A400FA/6** to recognize Nunchuk/Classic; otherwise skip that *initial* child read. (2) Classify known TR name or Nintendo PID **0330** as `gen20`, load normal inputs and **BUILTIN_MP** module (stops periodic idle MP polling, *not* every startup probe). [type/init](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L811-L905), [modules](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L570-L605), [builtin flag](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-modules.c#L2630-L2667).

(3) First worker reconciliation initializes normal A400 and inactive A600: **A400F0=55**, **A400FB=00**, **A600F0=55**, **A600FB=00**, reads **A600FA/6**, and reads **A400FA/6** for the child. Absent accessory can make A400 initialization fail; the worker does not treat that alone as missing MP. It accepts inactive MP if the read length is exactly six and **byte 5 = 0x05**. [registers](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L411-L557), [reconciliation](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L1100-L1162), [worker](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L1208-L1224).

(4) Load MotionPlus evdev child on successful probe. **Opening the MP evdev node** raises `MP_USED`, schedules another reconciliation and changes the data report mode. The mode write is **A600FE=04** (MP only), **05** (Nunchuk), or **07** (Classic); mapped **A400FA/6** should end respectively in **04 05**, **05 05**, **07 05**. Resend **0x15** status and reset **0x12** data mode as needed; six-byte gyro and alternating child frames produce gyro `ABS_RX/RY/RZ` plus child evdev node. [map/IDs](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L489-L558), [sensor open](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-modules.c#L2712-L2782), [mode transition](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L1163-L1205), [status reset](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L1414-L1449).

**Failures:** No response/length mismatch/byte 5 not 05 prevents MP child creation but may leave base input working. `BUILTIN_MP` suppresses periodic idle MP polling, so retry depends on scheduled status/hotplug work. **External-style identity A6200005 is accepted by kernel's loose predicate**; kernel itself does not insist on built-in A4200005. [probe](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L513-L530), [poll](https://github.com/torvalds/linux/blob/v6.12/drivers/hid/hid-wiimote-core.c#L899-L933).

### xwiimote / xwiishow — **kernel bound**

Requires an underlying HID `wiimote` parent, reads `devtype` and evdev children, and issues **no independent Wii register read/write**. Opening MotionPlus evdev triggers the kernel's `MP_USED` mapping path. MP-only is just MotionPlus events; Nunchuk and Classic are sibling extension inputs; no MotionPlus node means no xwiimote gyro. [parent](https://github.com/xwiimote/xwiimote/blob/4df713d9037d814cc0c64197f69e5c78d55caaf1/lib/core.c#L335-L393), [interface opens](https://github.com/xwiimote/xwiimote/blob/4df713d9037d814cc0c64197f69e5c78d55caaf1/lib/core.c#L611-L672), [ABS gyro](https://github.com/xwiimote/xwiimote/blob/4df713d9037d814cc0c64197f69e5c78d55caaf1/lib/core.c#L1045-L1090).

### SDL Wii HIDAPI — both PIDs accepted, **Linux kernel-managed MP**

Device initialization reads **A400FE/2** (mapped/normal extension ID suffix); error **7** is accepted as “no extension memory”. On uninitialized or active MP, may write **A400F0=55**, **A400FB=00**, then reread **A400FE/2**. Joystick open repeats extension initialization and probes **A400FE/2**, then **A600FE/2** if necessary (not `A600FA/6`). A two-byte masked result `value & 0xF0FF == 0x0005` indicates MP. [read parser/reset](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L284-L382), [MP state](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L385-L427), [device/open](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L677-L820).

For MP-only it chooses **04**, Nunchuk **05**, Classic/Gamepad **07** — but **on Linux it intentionally does not write A600FE**, delegating mapping to `hid-wiimote`. Conditional **0x12** selects e.g. **0x30** base, **0x32** extension, **0x35** extension/sensor, with periodic **0x15** status. OpenJoystick registers **SDL gyro for MP-only and Nunchuk, but not for pinned Classic/Gamepad branch**, even if the raw device has MP packets. [mode Linux](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L457-L491), [mode outputs](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L550-L585), [sensor registration](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L773-L820), [periodic status](https://github.com/libsdl-org/SDL/blob/877399b2b2cf21e67554ed9046410f268ce1d1b2/src/joystick/hidapi/SDL_hidapi_wii.c#L1540-L1568). Probe failure means no SDL gyro registration, not necessarily base-controller failure. Unbinding the kernel on Linux does **not** automatically make this driver activate MP.

### Dolphin ControllerInterface — native Wii Remote input

Conditional task order: **0x15** status; LED **0x11** with ACK; **0x12**, native data mode **0x37** with ACK; EEPROM accel-calibration **0x0016**; optional IR and speaker configuration/ACK. Some steps retry or stop before extension setup if their own readiness gates fail. [initial tasks](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L340-L445).

When extension status says connected, write **A400FB=00**, read **A400FA/6**, and initialize **A400F0=55** if the normal child ID is unsupported. For an inactive MP, poll **A600FE/1** for readability (not `A600FA/6`); then **A600F0=55**, **A600FE=04/05/07** according to desired mode. Wait for reset/status or debounce and reread **A400FA/6**, where last byte **05** identifies mapped MP. [sequence](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L449-L540), [ID parser](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L851-L879), [mode write](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L1049-L1069).

**MP-only:** successful active MP → **A40020/32** gyro calibration → decode six-byte gyroscope. **Nunchuk/Classic:** gyro frame flags child attached; read **A400F6/4**, parse split child ID, optionally change to mode **05/07**, then **A40020/32** MP calibration and **A40040/16** downstream calibration. Child data decoded separately. [F6 and calibration](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L543-L657), [extension desired modes](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L709-L742), [gyro flags](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L1352-L1403). No ControllerInterface **F7 challenge** or `0x50` read. MP non-response backs off or disables desired mode; active indicator is **mode state**, not permanent physical Plus presence. [fallback](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L660-L668).

### Dolphin Real Wii Remote slot — **source reference only; never run**

At link, sets noncontinuous core report mode; subsequent **game/SDK-issued** output reports are forwarded to real transport, and input reports are forwarded back. Its host does **not** run the ControllerInterface MP setup/calibration ladder. Thus no game-independent F1/F7/`0x50` or Plus startup requirements can be established; `0x50` remains a possible guest gate described in [#49](wii-motionplus-challenge.md). The balance-board-specific A400 probe in this source is *not* a generic Real Remote requirement. [report forwarding](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/Core/HW/WiimoteReal/WiimoteReal.cpp#L169-L267), [I/O](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/Core/HW/WiimoteReal/WiimoteReal.cpp#L295-L332), [host report path](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/Core/HW/WiimoteReal/WiimoteReal.cpp#L417-L478).

### Cemu native Wii HIDAPI

After HID detection of **0306/0330**, send **0x15** status. Status processing configures IR, requests EEPROM accel calibration **0x0016/8** if absent, probes **A600FA/6**, and initializes attached extension with **A400F0=55**, **A400FB=00**, **A400FA/6** if status extension bit **0x02** is set. These queued operations are not a stable global order and may repeat. [status](https://github.com/cemu-project/Cemu/blob/29f2f1fae4631e2317977debd9eacd55cc28dd7d/src/input/api/Wiimote/WiimoteControllerProvider.cpp#L55-L70), [branch](https://github.com/cemu-project/Cemu/blob/29f2f1fae4631e2317977debd9eacd55cc28dd7d/src/input/api/Wiimote/WiimoteControllerProvider.cpp#L239-L274), [requests](https://github.com/cemu-project/Cemu/blob/29f2f1fae4631e2317977debd9eacd55cc28dd7d/src/input/api/Wiimote/WiimoteControllerProvider.cpp#L925-L950), [EEPROM](https://github.com/cemu-project/Cemu/blob/29f2f1fae4631e2317977debd9eacd55cc28dd7d/src/input/api/Wiimote/WiimoteControllerProvider.cpp#L1012-L1014).

**Important Plus compatibility trap:** Cemu routes register read replies by *lower 16-bit address*, so the `A600FA` and `A400FA` responses share the same extension-ID handler. It knows the **built-in inactive A4200005** value but this branch only logs “inactive”; the **external-style A6200005** branch calls **A600F0=55**, **A600FE=04** and stores MotionPlus present. Do not falsify a retail ID to satisfy Cemu without a named creation-time compat decision. [ID constants](https://github.com/cemu-project/Cemu/blob/29f2f1fae4631e2317977debd9eacd55cc28dd7d/src/input/api/Wiimote/WiimoteMessages.h#L25-L60), [read handling](https://github.com/cemu-project/Cemu/blob/29f2f1fae4631e2317977debd9eacd55cc28dd7d/src/input/api/Wiimote/WiimoteControllerProvider.cpp#L275-L381), [activation](https://github.com/cemu-project/Cemu/blob/29f2f1fae4631e2317977debd9eacd55cc28dd7d/src/input/api/Wiimote/WiimoteControllerProvider.cpp#L925-L950).

Nunchuk/Classic identification causes **A40020/16** calibration read, not F6/40; when MP maps over the bank the reply can be MP data, not child data. Reporting mode follows extension/IR/acceleration flags, but the pinned code does not select an extension mode simply because MP is present. Actual decoded MP gyro remains **unverified and source-path limited** by the earlier [#47](wii-motionplus-consumer-comparison.md) unreachable MotionPlus visitor/export finding. [calibration](https://github.com/cemu-project/Cemu/blob/29f2f1fae4631e2317977debd9eacd55cc28dd7d/src/input/api/Wiimote/WiimoteControllerProvider.cpp#L324-L431), [report modes](https://github.com/cemu-project/Cemu/blob/29f2f1fae4631e2317977debd9eacd55cc28dd7d/src/input/api/Wiimote/WiimoteControllerProvider.cpp#L1015-L1045). Error 7 is logged and skipped, ACK errors are logged; no specific Plus game success follows.

### wiiuse — source reference **only**, native Bluetooth L2CAP

Probes **A600FA/6**; recognizes 32-bit inactive built-in **A4200005** and external **A6200005** plus mapped/unmapped variants, from last four ID bytes. A mismatch clears MP-present. On success writes **A600F0=55**, **A400F0=55**, **A400FB=00**, updates IR/report mode. Enabling MP writes **A600FE=04** (solo) or **05** (Nunchuk); waits, reads mapped **A400FA/6** and recognizes trailing mode IDs **A4200405 / 0505 / 0705**. Nunchuk interleaving/gyro decode uses packet flags and initial sample zeroing. [probe/init](https://github.com/wiiuse/wiiuse/blob/e769bd73860a4f941bd110ebae5a790f968b71e3/src/motion_plus.c#L45-L104), [mapped handshake](https://github.com/wiiuse/wiiuse/blob/e769bd73860a4f941bd110ebae5a790f968b71e3/src/motion_plus.c#L106-L166), [mode](https://github.com/wiiuse/wiiuse/blob/e769bd73860a4f941bd110ebae5a790f968b71e3/src/motion_plus.c#L170-L205), [gyro/child](https://github.com/wiiuse/wiiuse/blob/e769bd73860a4f941bd110ebae5a790f968b71e3/src/motion_plus.c#L244-L315), [ID constants](https://github.com/wiiuse/wiiuse/blob/e769bd73860a4f941bd110ebae5a790f968b71e3/src/wiiuse_internal.h#L227-L242).

**Classic limitation:** pinned decoder explicitly does **not** implement Classic passthrough data although mapped Classic ID is recognized. The enable API has only modes 04/05, not explicit 07. Actual Linux wiiuse requires L2CAP and cannot accept current virtual UHID; that is a transport limitation, not proof of a bad Plus protocol. [mode](https://github.com/wiiuse/wiiuse/blob/e769bd73860a4f941bd110ebae5a790f968b71e3/src/motion_plus.c#L170-L205), [unimplemented Classic](https://github.com/wiiuse/wiiuse/blob/e769bd73860a4f941bd110ebae5a790f968b71e3/src/motion_plus.c#L275-L315).

## Q4. F6, 40 and F7 shims on a Plus

The shim address bank should **not move** simply because MotionPlus is built in: scope is **mapped A400 when a downstream child exists**, not inactive A600 and not the physical MP-presence flag. Dolphin CI conditionally needs **F6/4 identity + F7 at its second byte** and **40/16 child calibration** for Nunchuk or Classic, after `A40020/32` gyro calibration. **MP-only needs neither F6 nor 40**. SDL/kernel/xwiimote/Cemu/wiiuse do **not** require F6/40 in reviewed paths. Cemu instead requests normal `A40020/16` and may see the wrong mapped bank. F7 **02** stays intentionally *non-ready*; challenge `0x50` remains unsupported. Whether real early/late integrated hardware does exactly any of these is **unknown**. [Dolphin exact gates](https://github.com/dolphin-emu/dolphin/blob/3eb30c7620b4475b2e0404228ba0d2b238a132f1/Source/Core/InputCommon/ControllerInterface/Wiimote/WiimoteController.cpp#L543-L657), [#46](wii-dolphin-attachment.md), [#49](wii-motionplus-challenge.md).

## Q6. virtualgamepad model, manifest, registry and realizations

**Source-grounded current state:** `WiiRemoteRevision::{Original, EarlyIntegratedPlus, Tr}`, creation-time F6/40 compatibility options, and `WiiRemoteState` exist already [source](https://github.com/anderstvoss/virtualgamepad/blob/1c810c5035c3bafb6543916ff06cb70ef6f340ab/crates/gr-curated-controllers/src/wii_remote.rs#L8-L45). Compiled registry entry **`virtualgamepad.wii-remote`** already exists [registry](https://github.com/anderstvoss/virtualgamepad/blob/1c810c5035c3bafb6543916ff06cb70ef6f340ab/crates/gr-controller-wire/src/registry.rs#L106-L124); accepted target surfaces are `linux.uinput` and `linux.uhid.bluetooth` [current acceptance](https://github.com/anderstvoss/virtualgamepad/blob/1c810c5035c3bafb6543916ff06cb70ef6f340ab/acceptance/virtualgamepad.wii-remote.toml#L1-L12). GUI can select revision at creation. An “independent controller model” here can mean a separate *curated revision personality*, not necessarily a new public family ID.

**Preferred approach:** retain `virtualgamepad.wii-remote` family ID, select existing `WiiRemoteRevision::Tr` under Wii Remote card **Advanced options** at creation, display “Wii Remote Plus”, and add **TR-scoped manifest and acceptance rows** with independent native UHID identity/startup/gyro/child qualification. Share source-backed original base button, accelerometer, IR, speaker/LED/rumble, common EEPROM routing and event shapes, but never automatically inherit a passing Original acceptance row as TR acceptance. `linux.uinput` may reuse base+gyro evdev semantics but **cannot prove PID-dependent HID binding**; `linux.uhid.bluetooth` requires fresh TR-specific tests. **Do not infer `EarlyIntegratedPlus`** from PID 0306.

**Alternative owner decision:** if Plus must be a *new public registry controller family* rather than an advanced Wii Remote revision, use proposed ID **`virtualgamepad.wii-remote-plus`** with own compiled `FamilySpec`, manifest/acceptance file (e.g. `acceptance/virtualgamepad.wii-remote-plus.toml`), GUI/catalog adapter and explicit `linux.uinput`/Bluetooth UHID realizations. That entails a public API/catalog change. Avoid duplicate registry personalities exposing the same Plus object without owner sign-off; also decide whether renaming enum `Tr` to `Plus` is warranted (API compatibility issue).

| Needed model change | Priority / explicit decision |
| --- | --- |
| `0330` Bluetooth identity, name and TR creation selector | **Discovery required**; public registry ID and descriptor-change breadth **owner decision** |
| Permanent internal-MP-present state **separate** from MP active mode, downstream attached and kernel `MP_USED` | **Gyro required**; product variant must not use status extension bit as physical MP |
| Inactive MP identity + FE readable probe, `A600F0/FB` initialization, 04/05/07 mode mapping and mapped FA identity | **Gyro required**; full integrated ID bytes **unknown**, owner-reviewed compat profile needed |
| Status-triggered reset, ACK/retry and 6-byte MP gyro/child frame tagging | **Gyro required**; reuse external codec with strict per-revision tests |
| EEPROM/MP/child calibration policy, F6 mirror and A40040 copy | **Dolphin native gyro + child required**; real data import only; shims already opt-in at creation |
| Retail descriptor / SDP differences, F7/0x50 challenge, physical CRC and gain, and a separate new registry ID | **Optional/deferred fidelity gates**, or **owner decision** if current emulation architecture cannot realize selected identity |

**No API, descriptor, codec or provider implementation changes are authorized in this PR.** All specs are source-backed consumer expectations, not proof of real integrated-MotionPlus hardware fidelity.

# Steam client detection — direct wired Triton (28de:1302)

**Status:** source-only research lead; no Linux host, hardware, client binary, local capture, virtualgamepad edit, or live Steam acceptance in this lane. **Date:** 2026-11-04. **Scope:** virtualgamepad #304 / D9 and #159, Steam Stable `1792618285`. All proposed implementation changes below are **compat**; none authorize copying measured retail attributes or changing the local buildout.

## 0. What is established

The D9 C6 virtual `linux.uhid.usb` device has the *exact physical* 372-byte 1302 HID descriptor (raw SHA-256 `315a037c849ef9510d222ae520bb18c1b72552d26eb116c91b0750901a5c51fd`); Linux 7.3 binds `hid-steam`, SDL Triton recognizes it and decodes input, but the named Steam client opens the hidraw node without listing it. A real controller on the same host *is* listed. UHID is not universally rejected (D9 also has a listed virtual DualSense). See [C6 acceptance](https://github.com/anderstvoss/virtualgamepad/blob/main/docs/C6_D9_ACCEPTANCE.md#L73-L80), [Steam design](https://github.com/anderstvoss/virtualgamepad/blob/main/docs/STEAM_CONTROLLER_2026.md#L107-L159), [current codec](https://github.com/anderstvoss/virtualgamepad/blob/main/crates/gr-curated-controllers/src/steam_controller_2026/codec.rs#L238-L326), corpus `steam-s3-1302-report-shapes` and `steam-s3-1302-usb-interface`. This is a negative *Steam-listing* result, not failure to enumerate HID.

From one attempted virtual run, feature-report-1 SET command counts are `0xae×24`, `0x83×364`, `0x85×7`, `0x8e×7`, `0x87×40` (key **9 ×33**, key **50 ×7**). All SETs had 64-byte buffers. The trace did **not** record originating process: kernel, SDL, Steam and other readers cannot yet be separated. In particular the 364 GET-attributes command writes are *suspicious for retry*, **not** proof Steam issued all 364. Feature **report ID 1** is distinct from the inner `0x83` command and from **output report ID 0x83** (haptic LFO). `0x87` SET_SETTINGS is likewise distinct from output report ID `0x87` streaming.

## A. The attribute response (`0x83`)

Wire: 64-byte numbered HID feature buffer: `[report_id=1, opcode=0x83, payload_len, (tag:u8, value:u32-le)*, padding]`. In a valid 5-entry response, `payload_len=25` (`0x19`). A source's **attribute enum** does *not* imply that its consumer requests all those IDs, validates them or expects a particular nonzero firmware value.

**SET failure:** UHID SET returns a completion status (not automatically a feature response body). On rejected key50, the virtual codec sends Unsupported; the host can see a failed HID SET ioctl/control transaction. SDL's lizard writer ignores the return in Update, its explicit sensor-enable returns false on failure; Linux's lizard setter is void. A private Steam disqualification is **inferred only**. Do not silently claim that accepting unknown keys changes hardware, persists settings or passes all follow-up reads. iczero [dissector:3–19](https://github.com/iczero/steam-controller-stuff/blob/83c46d7c5711f7497f83336526755fbf50d0c5af/dissector.lua#L3-L19) supplies command names but no SET acceptance proof.

## Follow-up and falsifiability

- **Minimum Steam-only log:** stage (discovered, opening, initialization, dropped), PID and bus class/interface flag, error/timeout code, setting key, feature index and report counts with timestamps. Process-origin labels if available; otherwise state *unknown*.
- **Minimum physical USB comparison:** paired Sessions 1 and 3, report ID, command, direction, size, status, `0x83` attribute **tag IDs and value type** (not values unless authorized), `0x87` setting keys and value categories, string index (not string), and whether `0x85/0x8e` were kernel-only.

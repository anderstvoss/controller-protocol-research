## Pinned rule provenance

- **Canonical Valve source (reuse, don't duplicate):** `steam-client-udev-60-steam-input`, 60-steam-input.rules, lines **25–56**. USB and Bluetooth hidraw rules for Sony and Nintendo with `MODE="0660"` and `TAG+="uaccess"`; *no dedicated 045e:028e/0719* rule found in this pinned public file. 60-steam-input also grants `uinput` (line 5), but installation and effective ACL depend on host policy. A rule in a repo is not proof that it was installed.
- `udev-systemd-input-id-rules` (`60-input-id.rules` 1–20) invokes input_id, `udev-systemd-input-id-builtin` (`src/udev/udev-builtin-input_id.c` 157–321) decides joystick by keys/axes and sets `ID_INPUT_JOYSTICK=1`; `udev-systemd-uaccess` (`70-uaccess.rules.in` 72–73) grants seat-dependent ACL for input joystick. This is **not** a blanket hidraw grant.
- `udev-systemd-evdev-hwdb`, `udev-systemd-input-id-hwdb`: pinned hwdb may influence joystick metadata and mappings but cannot be assumed installed/unmodified by a distribution; config, local overrides and active seat matter.
- `udev-virtualgamepad-uinput`, `udev-virtualgamepad-uhid`: virtualgamepad's *opt-in* group `virtualgamepad-uinput`/`virtualgamepad-uhid` grants `0660` on **creator** devices. These are distinct from consumer input/hidraw nodes and from USB control transfers. No runtime permission evidence.
- `steam-client-udev-sony-hidraw-grants`, `steam-client-udev-ds4-hidraw-grants`, `steam-client-udev-switch-pro-hidraw-grants`, `steam-client-udev-xbox360-no-specific-grant`, `udev-joystick-uaccess-heuristics`, `udev-virtual-device-creator-access` are this PR's evidence-role-consumer, source-only claims.

**What fails if missing:** no `/dev/uinput` access → virtual event node cannot be created; no `/dev/uhid` access → UHID virtual device cannot be created; no event ACL → evdev/SDL-event/RetroArch/evtest cannot read generated events; no hidraw ACL → direct SDL HIDAPI, Wine hidraw and other raw feature/report clients may fail while kernel evdev still works; missing `ID_INPUT_JOYSTICK` → input may not receive seat ACL or joystick classification. A public `uaccess` TAG only *requests* seat ACL; it is not an unconditional mode rule. Never suggest world-writable `0666` or auto-install rules without owner review.

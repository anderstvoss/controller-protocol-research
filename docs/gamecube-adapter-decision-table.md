# GameCube adapter — uinput compatibility versus faithful USB decision table

**GameCube USB research, prep for #296** · Source-only engineering decision matrix. **All host tests not run.** No virtualgamepad code changes or acceptance claims. A source-code decoder is not evidence of physical hardware behavior.

| Functional deviation | Consumer expectation, source-only | `linux.uinput` initial choice | Faithful USB-level behavior / No evidence | Claim IDs |
| --- | --- | --- | --- | --- |
| Four ports and per-port presence | SDL and Dolphin associate four logical ports with one adapter; ToadKing creates/destroys uinput devices on transitions | Up to four plain evdev pads with independent create/remove; no adapter parent handle exposed to consumers | 37-byte 0x21 report for one USB device with per-port status 0x10/0x20 | `gc-adapter-port-type-bits`, `gc-adapter-input-report-layout`, `gc-adapter-toadking-four-uinput-pads` |
| Wired versus WaveBird | SDL and Dolphin distinguish status types; SDL suppresses wireless rumble | Controller type stays internal metadata; one evdev shape for each present port | Preserve wired/WaveBird type, separately from presence; other status bits **No evidence** | `gc-adapter-port-type-bits`, `gc-adapter-rumble-output`, `gc-adapter-remaining-status-unknown` |
| Analog L/R vs digital click | SDL parses analog axes and digital trigger-bottom buttons; ToadKing emits ABS_Z/RZ plus EV_KEY | Two continuous trigger axes and **two independent digital click events**; never derive click merely from axis threshold without explicit policy | 9-byte port block retains independent analog L/R and click bits | `gc-adapter-button-bits`, `gc-adapter-input-report-layout`, `gc-adapter-toadking-evdev-range` |
| Stick axes, ranges, neutral | ToadKing raw axes 0..255 or narrower ranges, inverts Y; Dolphin first-present sample becomes origin; SDL widening range | Configure explicit ABS min/max/flat/fuzz, preserve axis sign and first neutral frame; source-specific default mapping, not physical center truth | Raw byte-domain values sent per-port; calibration learned by each consumer; true retail center **No evidence** | `gc-adapter-consumer-neutral-calibration`, `gc-adapter-toadking-evdev-range`, `gc-adapter-hinara-kernel-evdev` |

| WaveBird rumble | SDL and Dolphin skip it; ToadKing checks wired type | Do not falsely advertise effective rumble for wireless port, or label attempted effect as successful | Keep type gate; hardware rumble capability **No evidence** | `gc-adapter-port-type-bits`, `gc-adapter-rumble-output` |

## Scope decision

Choose `linux.uinput` first for playable four-pad evdev behavior; USB-level faithful realization remains explicitly conditional on #258 host permissions and the virtualgamepad USB-provider gate. A UHID identity does not satisfy libusb-only adapter consumers. No universal raw `0x04` power or `0x02` brake semantics should be declared physically validated.

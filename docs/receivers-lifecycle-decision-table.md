# Receiver lifecycle patterns and ADR-0022 decision table

**Scope:** source-only comparison for [virtualgamepad #165](https://github.com/anderstvoss/virtualgamepad/issues/165). No host, receiver hardware, device captures, or vendor firmware were examined. Receiver slot IDs, Linux input-node lifetimes, Linux LED/player indicators, and GamepadManager player slots are distinct. This table compares consumers, not demonstrated faithful virtual hardware.

**Upstream lanes:** [Puck PR #127](https://github.com/anderstvoss/controller-protocol-research/pull/127) (merged; `docs/receivers-puck-consumer-lifecycle.md` on main); [Xbox 360 PR #128](https://github.com/anderstvoss/controller-protocol-research/pull/128) and [Xbox Wireless Adapter PR #134](https://github.com/anderstvoss/controller-protocol-research/pull/134) (drafts at survey time). Their `rcv-puck-*`, `rcv-x360-*` and `rcv-xwa-*` claims are **reused by reference, not duplicated**. The Xbox draft claims are not yet guaranteed to exist on main. Puck SDL Triton handles status 0x46 / 0x79; the earlier prompt's suggestion of 0x7b as an SDL presence report is superseded by the reviewed Puck brief.

## ADR-0022 decision and validation gaps

**Verdict: preserve ADR-0022 for the 0–4-slot Steam Puck target; do not generalize its slot maximum, node lifecycle, or companion taxonomy to every receiver without changes.** Current core rules—one receiver owner, typed slot-local state and output, sibling isolation under slot-local loss, receiver-wide terminal cleanup, transactional preflight/rollback, and never replaying uncertain stateful output—are consistent with all reviewed consumers. No reviewed *child-slot-only* failure is shown to destroy siblings. **Logitech DJ is the explicit shared-failure counterexample**: loss of a required receiver USB interface tears down *all* child HID nodes, even if other interfaces remain bound; that belongs in receiver-wide failure handling.

**Input node / epoch decision:** Puck, Xbox 360 xpad and xone destructively unregister the child and create new objects on reconnect; user-space must expect a new joystick instance (exact evdev path reuse is unmeasured). DS4 dongle preserves probe-created nodes during ordinary controller disconnect, and DJ preserves paired child nodes through link-loss while destroying them on unpair. A durable internal protocol-slot identity must not imply either a stable Linux event node or a new one: record a new presentation epoch **only when a presentation is destroyed and recreated**. ADR-0021 presentation epochs remain deferred; this table is a requirement/gap, not a claim they are implemented.

**Untested / owner-only:** exact retail USB descriptors and interface grouping; simultaneous attach/leave races, sibling survival under partial transport fault, persistent pairing identity, absent-slot output actuation, uncertain output delivery, SDL device hotplug sequence, and whether a proposed `dummy_hcd` / USB/IP receiver actually binds the intended driver. A reduced uinput gamepad proves only post-driver compatibility. No host or physical test was run in this survey.

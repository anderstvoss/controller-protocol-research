# Switch 1 Joy-Con — source-only consumer survey (D)

**Joy-Con research, prep for virtualgamepad #297.** Every suggested host test is **not run**; no physical Joy-Con, virtual Joy-Con, Charging Grip or host has been exercised. Individual halves 057e:2006 (L) and 057e:2007 (R) are the native targets. A combined 057e:2008 device is an **application/daemon-generated identity**, not another physical Bluetooth personality (existing `joycon-joycond-pair-combination`, `joycon-sdl-hidapi-pair-combination`). The grip 057e:200e is USB and separate.

Source pins: Linux `4056b3c` and v5.16, SDL3 `535d80b` (3.2.0-era source pin), SDL2 tag `release-2.30.12` (commit `8236e01`), joycond `0df025a`, Steam rules `22ec85e`, and preexisting `parity-g-*` source records. Pins are **specific revisions**, not evidence of the installed host versions.

## Kernel history and 7.3+ target

Upstream Linux v5.15 lacks `drivers/hid/hid-nintendo.c` while **v5.16 already includes the Joy-Con L/R HID table, Charging Grip USB entry and the IMU parsing/enable path** (new pinned `joycon-d-linux-v516` source). Therefore **v5.16 is the earliest mainline release supported by this bounded release-tag comparison** for all three. Later versions may change rate limiting and capabilities; source pin `4056b3c` is the separate current detailed source under test. An Arch 7.3+ target would be *newer than the first-support version*, but **the installed kernel release, config, hid-nintendo binding and run results are not observed**. Do not equate target version with measured host presence.

## Cross-consumer qualification conditions

Direct HID and evdev can both enumerate, and joycond may hide the main physical event node. Record which path owns subcommands, whether multiple readers conflict, and whether pairing duplicates button input. Validate native report behavior (0x21 ACK, SPI, 0x30, IMU and rumble) separately from application-level gamepad mapping. No source-only result authorizes acceptance promotion.
